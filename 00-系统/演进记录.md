# 演进记录

> 记录 MyBrain 的结构性调整。这里只写已经发生的变化，不写宏大愿望。

## 2026-05-26：第一轮轻量重构

### 背景

MyBrain 已经从早期内容生产 vault 演进成混合系统：个人战略、旧规则、AI 协作资产、素材、草稿、已发布内容和复盘需求同时存在。旧版“宪法”和 SOP 仍在根目录指挥系统，造成当前规则不清。

### 本轮做了什么

- 新增 `00-系统/当前协议.md`，作为当前最高优先级的轻量协议。
- 新增 `00-系统/AI协作说明.md`，明确人脑与 AI 的职责边界。
- 新增 `00-系统/内容工作流.md`，把当前主线收束为捕获、素材、选题、创作、发布、复盘。
- 新增 `00-系统/资产索引.md`，作为当前资产入口。
- 新增 `10-捕获/收件箱.md`，作为新的低摩擦捕获入口。
- 新增 `30-选题/选题池.md`，作为素材到创作之间的决策中枢。
- 新增 `50-已发布/复盘模板.md`，让已发布内容进入反馈回路。
- 新增 `90-档案/旧规则/README.md`，说明旧规则如何被看待。
- 给旧版控制文件加了状态说明，降权但不删除正文。

### 本轮没有做什么

- 没有全量移动旧文件。
- 没有统一所有文件名。
- 没有删除废案。
- 没有重写已发布内容。
- 没有把系统设计成新的强规则宪法。

### 下一轮建议

围绕真实输出推进，而不是继续抽象整理：

1. 选一篇已发布内容，用 `50-已发布/复盘模板.md` 做一次复盘。
2. 从现有灵感和视频日记中提 5-10 个候选，填入 `30-选题/选题池.md`。
3. 下一条内容开写时，测试 `当前协议 -> 选题池 -> 草稿 -> 复盘` 这条链路是否顺手。

## 2026-05-26：第二轮核心资产接入

### 背景

第一轮建立了新骨架，但旧系统里的有效内容还没有嵌入，新系统仍偏空。第二轮开始把旧资产重新分配岗位。

### 本轮做了什么

- 从 `【重要】IP 定位.md` 提炼出 `00-系统/IP定位.md`。
- 从 `【旧，ai早期写的】SOP.md` 提炼出 `00-系统/常用流程.md`。
- 把旧版 `【重要】内容工作流.md` 中的语音输入、外部样本库、多媒体联动、手动分发、反馈复盘等有效判断接入新版 `00-系统/内容工作流.md`。
- 把旧 `Claude 资产索引.md` 中仍可调用的方法和 skill 接入 `00-系统/资产索引.md`。
- 从 `灵感精选/【优选】优选选题.md`、`视频日记/视频日记选题储备.md`、`灵感精选/不吐不快.md`、`灵感/自媒体灵感.md` 中抽取第一批选题，写入 `30-选题/选题池.md`。

### 本轮仍然没有做什么

- 没有移动旧素材目录。
- 没有全量整理 `灵感/`、`灵感精选/`、`运营相关/`。
- 没有替用户决定最终选题，只标记为待确认或待补素材。

## 2026-05-26：收缩过度设计

### 背景

第二轮仍然写了太多“协作边界”和“常用流程”，有重新变成强规则的倾向。用户指出当前真正需要的是把混乱结构理顺，而不是提前设计一套固定工作流。

### 本轮做了什么

- 删除 `00-系统/AI协作说明.md` 和 `00-系统/常用流程.md`。
- 将 `00-系统/当前协议.md` 压缩成系统地图。
- 将 `00-系统/内容工作流.md` 压缩成轻量说明。
- 将根目录旧规则迁到 `90-档案/旧规则/`。
- 将仍有当前价值的根目录思考迁到 `00-系统/当前思考/`。
- 将根目录零散入口迁到 `90-档案/零散入口/`。

## 2026-05-26：大块资产归位

### 背景

用户明确指出：当前重点不是继续写规则，而是把原有混乱结构按意图收拾好。

- 将个人画像归到 `00-系统/个人画像/`。

- 将废案、旧规则、零散入口和低频资料归到 `90-档案/`。

### 本轮没有做什么
