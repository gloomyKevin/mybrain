# 文档工程实战包

把下面 4 个文件放进你项目对应位置。`<...>` 是占位符，按你项目情况填。AI 读到会自动理解。

---

## 目录结构

```
your-project/
├── CLAUDE.md                   ← 文件 1（项目根目录）
├── DEBUGGING.md                ← 文件 4（项目根目录）
├── .claude/
│   ├── tasks/                 ← 任务过程档（进 .gitignore）
│   └── templates/
│       └── task-template.md   ← 文件 3
├── docs/
│   ├── api/
│   ├── business/
│   └── architecture/
├── src/
├── .gitignore                 ← 文件 2（追加末尾）
└── README.md
```

## 文件 1 · `CLAUDE.md`

> 放项目根目录。Claude Code / Cursor / Codex CLI 每次都会自动加载。
> 用 Codex CLI 的改文件名为 `AGENTS.md`，内容一字不改。

```markdown
# <项目名> · 协作规范

## 技术栈

<按你项目情况列 3-5 行，只写会影响协作决策的（框架、数据库、测试工具、部署平台），不写小版本号>

## 禁改清单

以下文件 AI 不允许自动修改；只有人类明确指令时才能动：

- `*.lock` / `*.lockb` / `package-lock.json` / `yarn.lock` — 依赖锁
- `.env*` — 环境变量，任何情况不读、不展示、不修改
- `<你项目的代码生成目录，如 src/generated/** 或 prisma/migrations/**>`
- `docs/api/**` — 成品接口文档，仅通过约定流程更新

## 协作原则

- 最小充分变更：不改任务范围外的文件
- 先说方案再动手：涉及数据结构、API 形状、第三方依赖时，先给方案 + 等确认，再写代码
- 显式取舍：方案里列 2-3 个选项 + tradeoff，不要直接给一个
- 事实 / 推断 / 风险分开说

## 高风险操作（必须显式确认才可执行）

- 删文件或目录
- `git reset --hard` / `git push -f`
- 数据库 DROP / TRUNCATE / 批量 UPDATE / 批量 DELETE
- 批量改写超过 5 个文件

## 文档同步矩阵

改了代码后同时必须更新的文档：

| 改动类型 | 必须同步更新 |
|---|---|
| 新增 / 修改 API endpoint | `docs/api/<name>.md` + `docs/api/API.md` 索引 |
| 新增 / 修改业务规则 | `docs/business/<name>.md` |
| 架构级改动（新模块 / 拆服务 / 换框架） | `docs/architecture/overview.md` + 本文件技术栈段 |
| 引入 / 升级第三方依赖 | 本文件技术栈段 + `docs/architecture/dependencies.md` |
| 修 bug 不改接口 | 不更新文档；反复踩的坑写到 `DEBUGGING.md` |

## 任务档约定

- 每次新任务：在 `.claude/tasks/task-YYYY-MM-DD-<关键词>.md` 建档
- 档里按 `.claude/templates/task-template.md` 结构填
- 任务档不进 Git

## 验证三件套

<按你项目填真实命令，例如：>
- 类型检查：`<命令>`
- 单元测试：`<命令>`
- 构建：`<命令>`

## 规则优先级

- 用户明确指令 > 本文件
- 项目级 > 全局 > 默认
- 具体 > 抽象
```

## 文件 4 · `DEBUGGING.md`

> 放项目根目录。踩坑登记册。新人（含 AI）接手项目时第一眼翻这份。

```markdown
# 踩坑手册

一条坑一个入口，按日期倒序排。

## 条目格式

### <问题一句话描述>

- **现象**：
- **原因**：
- **解决**：
- **日期 / commit**：

---

## 示例

### Windows 下 `npm link` 报 EPERM

- **现象**：`npm link` 执行失败，提示权限错误
- **原因**：目标文件被 OneDrive 同步锁定
- **解决**：暂停 OneDrive 同步后重试
- **日期**：<YYYY-MM-DD>
```

## 附 · 上 Git 的 4 分类判断清单

**判断题只有一个：半年后还有人需要读吗？**

**不进 Git**：
- 运行过程档 — `task-*.md`、`what-i-did-*.md`
- AI 头脑风暴草稿 — `要不要上-trpc.md`、`方案对比-v3.md`、`临时思路.md`
- AI 会话转录 — `.claude/sessions/` 下任何文件
- 短期实验 — `poc-*.md`、`测试-*.md`

**进 Git**：
- API 成品 — `docs/api/<name>.md`
- 业务规则 — `docs/business/<name>.md`
- 架构成品 — `docs/architecture/overview.md`
- 协作规范 — `CLAUDE.md`、`<子目录>/CLAUDE.md`
- 踩坑手册 — `DEBUGGING.md`

---

## 落地 3 步

1. 把 4 个文件各自粘贴到对应位置，`<...>` 占位符按你项目情况填
2. 把文件 2 的 `.gitignore` 片段追加到项目根目录的 `.gitignore` 末尾
3. 新建空目录 `.claude/tasks/`、`docs/api/`、`docs/business/`、`docs/architecture/`

做完以上，下次你开 Claude Code / Cursor 写代码，AI 就有规范可循了。
