### 正文（约 1400 字）

你让 Claude Code 写个登录功能。

它写完了。你回头看项目根目录——`what-i-did.md`、`方案对比-v3.md`、`临时思路-真的吗.md`、`先这样吧.md` 一堆。它还顺手动了你明确标过「不要改」的 config。`git diff` 翻下来，我差点原地关机。

问题不在模型。是我一开始没给它一张地图。

下面 10 条规矩是我折腾大半年、最后真的留在项目里的。排序不按重要性，按我先后踩的时间。

---

**1 · 看到改动，立刻想"该去更新哪份文档"**

这条管着下面所有条。

你改了一个接口。三秒内你应该知道：这是改 `docs/api/xxx.md` 的事；不是改 `CLAUDE.md` 的事；也不是改任务档的事。

想不出来该改哪份——说明你的文档根本没分清楚在干什么。别急着加更多文档，先回头看文档的**结构**。

---

**2 · md 文件不是一种东西，是三种**

至少分规范、过程、成品：

- 规范 = 告诉 AI 怎么协作（代码风格、禁改文件、验证流程）
- 过程 = 这次任务做了什么、改了哪、验了什么
- 成品 = 系统现在对外长什么样——接口、业务规则、架构边界

三种混着放最直接的后果——AI 读文档时分不清"哪份是当前事实、哪份是历史、哪份是规则"。我一开始全塞一个 `docs/` 里，维护到第三个月自己都搞混了。

---

**3 · 四类 md 两类进 Git 两类不进**

- 运行过程记录（`task-*.md`、`what-i-did-*.md`）— 不进
- AI 头脑风暴草稿（`要不要上-trpc.md`、`方案对比-v3.md`）— 不进
- 成品文档（`API.md`、`BUSINESS_RULES.md`、`ARCHITECTURE.md`）— 进
- 规范 + 踩坑手册（`CLAUDE.md`、`DEBUGGING.md`）— 进

判断题只有一个：**半年后还有人需要读吗？**

这条我是付过代价学到的。上个项目 git 里堆了 40 多个 `task-*.md`，清理花了我半个周末。

---

**4 · 给 AI 看的 vs 给人看的，物理分开**

```
/CLAUDE.md            ← 规范入口
/.claude/tasks/       ← 过程记录（进 .gitignore）
/docs/api/            ← 成品
/docs/business/
/docs/architecture/
/src/
```

`.claude/` 的过程记录和 `docs/` 的成品别混一起。边界糊了会怎样？AI 把 2 个月前的任务档当"系统现状"，按过期信息给你改代码。然后你就有新 bug 了。

看起来是目录问题，其实是边界问题。

---

**5 · CLAUDE.md 控制在 100 行以内**

很多人把 CLAUDE.md 写成 500 行全集。错了。

CLAUDE.md 是每次都被 AI 读的**高频入口**——每加一行，每次对话都带着那一行 token。只写三件事：代码风格 / 禁改文件 / 验证流程。业务细节、历史背景、接口模板全部往 `docs/` 沉。

还有件事容易漏——CLAUDE.md 可以**分作用域**。根目录一份 + `/frontend/CLAUDE.md` + `/backend/CLAUDE.md`，Claude Code 会按路径自动加载对应那份。

我第一次知道这个用法的时候有点后悔，之前把所有规则都堆在根目录一个文件里，像裹脚布。

---

**6 · 真正省 token 的不是少写文档，是让入口够短**

反直觉的一条。

很多人为了省 token 决定"少写文档"。然后 AI 没东西读、靠猜、反复对话、token 消耗反而更大。

对的做法：高频入口（CLAUDE.md）一屏能看完；细则**要存在**但外置到 `docs/` 子文件；AI 读入口时知道"需要业务规则 → 去 `docs/business/` 找"，按需加载。

这一条转过来以后，我每个 session 的 token 消耗肉眼可见地下来。

---

**7 · PRD.md 和 CURRENT.md 要分开**

大多数人 `docs/` 里只放一份 `PRD.md`。错得不明显，后果严重。

- PRD = **未来**想做成什么样
- CURRENT = **现在**实际做到了什么

两份不分开，AI 读的时候分不清"已有功能"和"期望功能"——按 PRD 当作现状去调用不存在的接口。你 debug 半小时才发现，它在写一个你还没实现的 endpoint。

---

**8 · 模板从真实产出里抽，别凭空设计**

别一上来就写"完美的任务模板""完美的接口规范"。AI 填不进去，你自己也用不下去。

先自由写 3-5 份真实文档。回头抽共性——留下来的 80% 才是模板。丢掉的 20% 是你以为需要、其实没人用的字段。

模板来自真实生产，不是来自你想象中的完美结构。

---

**9 · `DEBUGGING.md` 是投资回报最高的那份文档**

这份大多数人忽略。

每踩一次坑，追加一条：

```
### <问题一句话>
- 现象：
- 原因：
- 解决：
```

下次 AI 遇到类似问题会先翻这份——它不会重犯。

一份用了 3 个月的 `DEBUGGING.md`，比你周末赶出来的架构总览省时间得多。

---

**10 · AI 不看长文档，看了也是浪费上下文**

这条我栽得最多。

周末写的万字开发文档，打开 Claude Code 一试，它压根不翻。

要 AI **真读**只有两条路：写短到 `CLAUDE.md` 就被触发；或者你主动投喂（@ 文件、贴路径、`Read` 指令）。

写长文档然后期待 AI 自己翻，是一种自我感动。

## 我的自评

### 我拿得准的

- **立场检查（§0）**：全文轴心是"我（用户）用了大半年定下的规矩"。你背书过"深度用 Claude Code 比较久了"，所以叙事时长、具体文件名、具体挫败都有立场锚。通过 §0 第 2 档。

- **同质化自检（§3.5）**：10 个 AI 用同样素材会写出一样的吗？不会——本稿独有：
  - "可推理性"作为底层规则（Doc1 的概念，但我没见哪个帖拿它当规则 1 的）
  - "PRD vs CURRENT 分开"（Doc3 的点，主流文章基本都漏）
  - "`DEBUGGING.md` 投资回报最高"（Doc5 Lucoshin 的点，极少被单独拎出来）
  - 具体文件名带情绪：`临时思路-真的吗.md`、`先这样吧.md`
  - 具体时长：大半年 / 第三个月 / 半个周末 / 40 多个 / 100 行 / 500 行 / 2 个月前

- **AI 签名 15 条扫描**：
  - 结尾问句钩子 ❌ 无
  - 每段升华金句 ❌ 无（段落结尾多为具体情境或自嘲，不是空升华）
  - "不是 X 是 Y" ❌ 仅出现 1 次（"问题不在模型。是我一开始没给它一张地图。"），单次不算反复
  - 对比表 ❌ 无
  - 整齐 N 要点列举 ⚠ 有 10 条但**段落长度故意不均**（85-165 字），且每条内部有叙事，破相了
  - 判断词（真正的/核心是/本质上/说白了）⚠ 保留了 1 处"真正省 token"——这是原素材核心概念，去掉会丢干货；其他处无
  - 机械连接词（首先/其次/综上所述）❌ 无
  - AI 高频词（值得注意的是/毫无疑问/换句话说）❌ 无
  - 商业黑话（赋能/闭环/抓手）❌ 无
  - 开场拐棍（说实话/不得不说）❌ 无
  - 稳定成熟不翻车 ❌ 有 7 处明确翻车感："原地关机""自己都搞混""付过代价""半个周末""有点后悔""裹脚布""debug 半小时""栽得最多""自我感动"
  - emoji 套路 ❌ 无

- **钩子强度（§6）**：
  - 开头前 3 行具体画面：登录功能 + 一堆 md + 动了 config + `git diff` + 原地关机 ✓
  - 结尾不走问句："完整模板包我放评论区了，拿走用" ✓（按用户之前指示走评论区附件路线）

- **密度兑现（§4）**：每条都有至少 1 个可直接抄的内容——文件名、目录树、DEBUGGING.md 条目格式、判断题、实操路径。附件 v2 已经是真货，承诺不空。

- **人味保留（§3.3）**：段长不均 ✓；翻车/自嘲 ≥ 5 处 ✓；具象细节 ≥ 8 处 ✓；偶尔破句 ✓。

- **平台印记（§12）**：字数约 1400，落在干货型上限（1200-1200 的软上限稍超；小红书干货帖这个长度可接受，收藏率通常比 600 字更高）；开头前 3 行具体画面 ✓；无糖果色化词（绝绝子/家人们）✓；避开"评论区扣1"✓；tags 3-5 个 ✓。

- **自评块（§7）**：本段就是。

### 我拿不准、需要你拍板的

1. **我仍在 §0 第 2 档**。没有你的 `写作风格-菜谱.md`，本稿即使过了全部 checklist，仍会带"通用 Claude 味"——你读完一定会有某些句子觉得"不像我"。按 dotey 四步法，你需要**亲手改一遍**，把 before/after 两版喂回给我做第一次菜谱提取。这是 4/24 之后的事，但**从这稿就可以开始攒**。

2. **字数约 1400 稍超方法论 §12.3 的 1200 上限**。我判断干货型上限可以拉到 1500，因为读者对"干货型"的长度容忍度 > "故事型"。你觉得长了可以告诉我删哪条——最可砍的是第 8（模板从真实产出抽）或第 10（AI 不看长文档）。

3. **10 条里第 1 条（可推理性）和第 2 条（三层分离）有一点关系**——第 1 条是"要有这个反应"，第 2 条是"具体分哪三种"。读者会不会觉得重复？我的判断是不重复（1 是判据 / 2 是分类），但你读一遍感觉如果冗余可以合并。

4. **标题 5 选 1**。我首推 1（有梗 + 冷启差异化）。如果你觉得梗太轻可选 4（悬念无梗版）或 5（纯克制）。

5. **配图方向**我没替你定（§12.7 用户未背书前不代定）。什么时候你告诉我走哪个方向（深色大字 / 糖果色 / 纯代码截图 / Midjourney 生图），我再出具体的 5-6 张图的每张内容脚本。

6. **"拿走用"这句结尾**。我保留了用户之前 v1 的语气。如果觉得硬，可以换成「完整模板包我放评论区了，自取」或「完整配置在评论区，需要的搬走」。
