# 橙皮书《Obsidian + Claude Code：用 AI 重建你的第二大脑》要点与我的判断

> 作者：花叔（AI Native Coder，30 万+ 粉丝，代表作小猫补光灯）
> 出版：2026-04-11，v1.0.0，58 页
> 本地原文：`[[Obsidian-AI-v1.0.0.pdf]]`

## 一句话总结

**Markdown + Claude Code 就是 2026 年个人 PKM 的最优解**；作者核心建议三件：
1. **CLAUDE.md** 作为 AI 的"员工手册"（规则路由）
2. **每个文件夹放 index.md**（目录索引，让 AI 进入即理解）
3. **Karpathy 的 "LLM Wiki 编译模式"**——让 AI 把 raw 素材**编译**成结构化 wiki 文章保留，而不是 RAG 每次重新检索

---

## 我认同、值得采纳的

### 1. "LLM 是编译器，不是检索器"（Karpathy 的核心洞察）

全书最有价值的一条。

RAG 的本质问题：每次提问都从零开始。你今天问 AI "X vs Y"，它搜原始笔记拼接回答；明天再问相关问题，再做一遍。**没有积累、没有正反馈**。

Karpathy 的方案：让 AI 读完原始素材后**写成 wiki 文章保留**。下次直接读 wiki，不再处理原始素材。**越用越厚**。

这恰好和 mybrain 之前设计的 `素材箱/ → 笔记/` 完全同构：素材箱 = raw，笔记 = wiki。**书不是给我们新结构，而是给现有结构命名、提供动力学解释。方向对了。**

### 2. CLAUDE.md 作为员工手册，靠"犯错触发规则"迭代

作者原话："每次 Claude Code 犯一个错，我就在 CLAUDE.md 里加一条规则。半年下来，从几行字长成了一个路由系统。"

**关键是别一次写完美**。我们现在项目 CLAUDE.md 已有，应该持续演化。

### 3. 每个文件夹放一个 index.md

简单到离谱，但效果显著。AI 进入一个文件夹不再逐个扫文件，先读 index.md（3 秒）就知道这个文件夹干嘛的、重要文件在哪。

**这是全书对 mybrain 最大的增量**——目前除了 `领域/_说明.md` 和 `备选/_说明.md`，其他目录都没有这层。

### 4. frontmatter 加 `摘要`（summary）字段

一句话说这条笔记是什么。AI 扫 vault 时不用读全文，看摘要就能判断相关性。**极高 ROI**，我们当前模板没有，应加。

### 5. obsidian-skills 插件

Obsidian 的 CEO Kepano 亲手做的 Claude Code Skills，教 AI 正确处理 `[[wikilinks]]`、callout、frontmatter、`.canvas` 等 Obsidian 专有语法。30 秒安装，没理由不装。

### 6. 用 Git 管理 vault

AI 改笔记 → `git diff` 看动了什么 → 不满意 `git checkout .`。给你"放手让 AI 大改"的自信。作者原话："没有 Git 你会犹豫，有 Git 你知道随时能回退。"

`.gitignore` 排 `.obsidian/workspace*.json`（布局文件频繁变化，不追踪）。

### 7. Raw → Wiki → Output 的三层分离思想（但我会改造）

书里：`raw/`（源材料，只增不改）→ `wiki/`（AI 维护的结构化知识）→ `output/`（基于 wiki 的产出）

映射到 mybrain：
- `素材箱/` = raw
- `笔记/` = wiki
- `项目/` 下的产出 = output（不单独建 `产出/` 目录，等量上来再说）

### 8. SCHEMA.md 的思路——用一份规范约束 AI 的创建行为

AI 不约束就会漂：今天标签叫 `#ai-tools`，明天叫 `#AI工具`。用一份明确规范把它钉住。我们的 `_模板.md` 已经承担了部分角色，但可以更系统化。

## 我不采纳、或要大改的

### ❌ 英文文件夹名 + 英文标签

书建议 tags 用英文（`#ai` 不用 `#人工智能`），说是 grep 搜索更稳。**这条已过时**。2026 年 Claude Code 对中文文件名/搜索一样稳。mybrain 坚持中文。

### ❌ fleeting / literature / permanent 三种笔记 type

卡片盒笔记法的 cargo cult。要你对每条笔记做一次分类决策，收益很低。**我们的 `状态` 字段（待办/进行中/等待中/搁置/已完成）已覆盖生命周期，够用。**

### ❌ Claudian 插件（在 Obsidian 侧边栏里跑 Claude Code）

本质是省一次 Alt+Tab。多一个插件多一份认知负担，终端开 Claude Code 完全够。**跳过。**

### ❌ Copilot for Obsidian 插件（vault 级 RAG 问答）

和 Claude Code 直接读 vault 功能重叠，引入了另一套 AI 范式。**工具膨胀，跳过。**

### ❌ 书对任务管理几乎空白

全书讲知识，不讲任务。项目管理那一节（§7.5）就是"每个项目一个文件夹+index.md"，没有 todo/等待/备选的区分、没有 GTD 的 clarify 流程、没有回顾仪式。

**mybrain 当前的任务系统（任务/项目/备选/领域/回顾/看板）明显比书里强。保留，一个字不改。**

### ⚠️ 书对"输入捕获"一笔带过

只说"扔进 raw/ 就行"，没有手机端捕获、截图、分享、播客的具体方案。

**我们的 `输入捕获方案.md` 比书里完整。保留。**

### ⚠️ 作者场景 = 内容创作者，工作流有偏向

作者是公众号/视频自媒体，7 个工作流里至少 3 个围绕"写文章"。如果你的场景不是高频写作，某些工作流（§7.4 写作工作流、§7.1 周报 wrapped）不直接适用。但"编译模式"的底层思想普适。

## 我对作者的批判性观察

1. **作者自己还没真正用过 Obsidian**（自序第一句坦承）。全书是基于"Cursor 文件树 + Claude Code + 裸 markdown 文件夹"的经验推断 Obsidian 会更好。洞察大体准确，但没有真正用过的踩坑经验——比如模板 C（raw/wiki/output 三层）实操起来远比描述的麻烦，作者没实践过就推荐。

2. **重"搭架子"，轻"用架子"**。架构、CLAUDE.md、SCHEMA.md 讲得很细；但"日常用起来以后怎么发现系统在烂掉"几乎没讲。**mybrain 的 `需关注看板` + 周回顾模板填的正是这个坑**——这个维度上我们比书里强。

3. **"40 万字以内不需要向量数据库"偏乐观**。作者自己没做过百万字规模实践，这个断言更多是基于上下文窗口的算术推断。实际到 10 万字+ 就该考虑 Smart Connections 做语义搜索辅助。

4. **发布时间是 2026-04-11（11 天前）**。很新，很多建议还没被时间验证。作者自己坦承还在迁移过程中。**读者得自己带判断。**

## 对 mybrain 的具体采纳建议（按优先级）

### P1 — 高收益、低成本、可立即做

1. **装 obsidian-skills**（Obsidian 设置 → 社区插件，搜 `kepano/obsidian-skills`），30 秒搞定
2. **所有 frontmatter 模板加 `摘要` 字段**——`任务/_模板.md`、`项目/_模板.md`、未来的 `笔记/_模板.md` 和 `素材箱/_模板.md`
3. **每个主目录加一个 `_索引.md`**——一段话说这个文件夹干嘛的 + 关键文件指针。当前只有 `领域/` 和 `备选/` 有
4. **vault 根目录 `git init`**（`.gitignore` 排 `.obsidian/workspace*.json`）。在让 AI 大动架构前必做

### P2 — 系统化升级

5. **正式建 `素材箱/` 和 `笔记/` 两个目录**，把"素材箱 → 笔记"显式定义为 mybrain 的 Karpathy 编译管道，写进 CLAUDE.md
6. **写 `笔记/规范.md`**（相当于书里的 SCHEMA.md）——定义原子笔记的命名、frontmatter、内部结构。让 AI 批量创建时有规矩可循
7. **升级根 CLAUDE.md**——加路由规则：收到什么类型的任务，先去读哪个文件/文件夹

### P3 — 等规模到了再做

8. 笔记/素材箱 文件数 > 100 时装 **Smart Connections**（语义搜索）
9. 在 CLAUDE.md 里写**自动化 skills**：例如"处理今天日记 → 扫日记 → 识别人名/书名/概念 → 搜 vault → 有则替换为 wikilink、无则创建 stub"
10. 产出类笔记积累 > 5 篇时考虑建 `产出/` 目录。当前不用

### ❌ 明确不采纳

- 英文命名
- fleeting / literature / permanent type 字段
- Claudian 插件
- Copilot for Obsidian 插件
- 书里的模板 A / B / C 直接套用（我们已有自己结构）

## 这本书在 mybrain 的整体定位

**不是"按书建架构"，是"用书补漏洞"。**

mybrain 当前架构（任务+知识双轨、总台+飞书分工）比书里更适合一个"个人总台"定位。书里有几个具体技法（index.md、摘要字段、raw→wiki 编译命名、obsidian-skills、Git 管理）是明显的增量，该吸收就吸收，其他保留。

**核心对齐验证：书证明了 mybrain 的大方向（Markdown + agent + 让 AI 维护）是对的，不是我一个人在瞎搭。**
