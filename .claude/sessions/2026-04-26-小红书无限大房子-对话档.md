## 阶段 12 · DeepSeek V4 Flash + 原 SKILL 直喂出稿

### 【Claude 操作】

- 写对话档（本文件）+ task-part prompt（包含段落骨架 + 用户原话两段）
- bash 拼接 SKILL.md 全文 + task-part 喂给 deepseek CLI
- raw 输出落 `.claude/experiments/2026-04-26-deepseek-skill-flash-v1-raw.md`
- 带 metadata 留档落 `.claude/experiments/2026-04-26-deepseek-skill-flash-v1.md`

### 【DeepSeek V4 Flash 输出 · 严重问题】

L1 / L2 不通过，L3 / L4 部分通过。整体未达标。

**主要失败**：DeepSeek 把 task-part 里写给它看的"组织标签"（「收口：xxx」「起源洞察：xxx」「形态：xxx」「工具：xxx」「卡点：xxx」）**当作要复述到正文里的"正文标签"**，文章变成了类似 PPT bullet point 结构。这是显著的指令理解失败。

**次要失败**：P1 钩子段提前把 P5 爆点段的兑现句"打在棉花上，不是没用力，是发力点一直在膨胀"用掉了，P5 又逐字重复一次。契诃夫之枪结构破碎。

### 【责任分担】

- label 复述：主要是 DeepSeek 指令理解能力（Claude 看同样骨架没犯这个错），但 task-part 用「收口：xxx」字面格式确实给了 DeepSeek 不好的 cue
- 钩子提前用爆点：纯 DeepSeek 判断失误

### 【关键观察】

在原 SKILL + 段落骨架 + 用户原话（同等输入）下，DeepSeek V4 Flash 的指令遵循能力**显著弱于** Claude Opus 4.7。

但有 caveat：可以改写 task-part 避开「收口：xxx」字面格式（改成自然语言描述），再跑一次看 DeepSeek 是否改善。这是测「DeepSeek 在更友好 prompt 下能否到位」，不是再测「同等约束下的真实能力」。
