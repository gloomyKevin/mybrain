# 内容生产管线 · 模型编排

> 这是 mybrain vault 的内容生产流水线编排说明。**测试期资产，放在 `.claude/` 隔离区，不进入正式笔记浏览**。
>
> 正式管道（收件箱 → 素材库 → 草稿 → 已发布）不受这套编排影响。

## 节点表 · 谁干什么

| # | 节点 | 内容 | 用谁 | 理由 |
|---|---|---|---|---|
| 1 | 素材清洗 | 去重、修语病、保留口语 | Claude Code | 结构化、长上下文 |
| 2 | HKR 质检 | 三轴打分 + 缺细节清单 | Claude Code | 跑 checklist |
| 3 | 角度候选 | 3-5 个候选 + 评估 | Claude Code（可并行 DeepSeek 出另一组候选） | Claude 偏结构感，DeepSeek 偏松弛口腔感（实测中） |
| 4 | 段落骨架 | 每段一句指向 + 锚点位置 | Claude Code | 结构化设计 |
| 5 | 写血肉 | 完整成稿生成 | Claude Opus（DeepSeek 可并行出候选） | 主稿 SKILL 服从 + 上下文一致；DeepSeek 候选作双视角对照 |
| 6 | L1-L4 自检 | 禁忌扫描 + 风格扫描 | Claude Code | 结构化执行 |
| 7 | 用户改稿 | 人 | 用户 | 卡兹克方法论核心步 |
| 8 | 反向提取迭代 | 从两版差异提口癖 | Claude Code | 结构化分析 |

当前主笔 Claude Opus（主会话）。DeepSeek 在节点 3 / 5 可作并行候选生成器（双视角对照），不主笔。具体在哪几个节点真值得用，仍在实测中。

## 工具链

### 全局（vault 外）
- `~/.claude/scripts/deepseek` — DeepSeek CLI 包装。stdin → stdout。读 `$DEEPSEEK_API_KEY`
- `~/.claude/scripts/khazix-shortform-style.md` — 卡兹克风格浓缩版（DeepSeek 专用）。约 1500 字

### 项目级（vault 内 `.claude/`）
- `.claude/管线编排.md` — 本文件
- `.claude/experiments/` — DeepSeek 实跑产物隔离区
- `.claude/templates/` — 预留

### 环境变量
- `DEEPSEEK_API_KEY` — 在 `~/.zshrc`，不进 git
- `DEEPSEEK_MODEL`（可选）— 默认 `deepseek-v4-flash`

## DeepSeek CLI 用法

```bash
# 基本：stdin 进，stdout 出
echo "你好" | deepseek

# 文件输入
deepseek prompt.md

# 指定模型 / 系统提示 / 温度
deepseek -m deepseek-v4-flash -s "you are an editor" -t 0.7 prompt.md
```

成本量级（V4 Flash）：单次约 5K input + 2K output ≈ 不到 1 分钱。

## 工作流（B 类 · 个人经验语音 → 短图文）

```
[1] 用户提供大纲 + 语音转文字原始稿
       ↓ Claude Code
[2] 事实清晰版（去重修语 / 保留口语 / 用户确认）
       ↓ Claude Code
[3] HKR 质检 + 缺细节清单 → 用户补
       ↓ Claude Code
[4] 角度候选 5 个 → 用户挑 1
       ↓ Claude Code
[5] 段落级骨架 P0-Pn → 用户挑 / 调
       ↓ Claude Opus 写血肉
       ↓（可并行候选：cat prompt.md | deepseek → DeepSeek 出对照稿）
[6] 主稿 +（可选）DeepSeek 候选稿
       ↓ Claude Code
[7] L1-L4 自检（禁忌扫描 + 风格扫描）
       ↓
[8] 用户改稿（卡兹克方法论核心步）
       ↓ Claude Code
[9] 反向提取用户口癖 → 对话级记忆
```

A 类（外部素材改写）流程类似，节点 1-2 替换为「素材整理 + 角度差提取」，其他相同。

## 留档规则

- **正式产出**：`草稿/小红书/<YYYY-MM-DD>-<标题关键词>.md`（vault 正式管道）
- **DeepSeek 实跑产物**：`.claude/experiments/<YYYY-MM-DD>-deepseek-v<N>.md`（隔离区，不污染笔记浏览）
- **对照实验**：同一选题 Claude 版进正式管道，DeepSeek 版进 experiments，等评估稳定后再决定是否切

## 2026-04-26 实验观察

跑了一轮 SKILL 长文写作横向对比（留档 `废案/2026-04-26-skill风格-模型横向对比/`）。这次跑的是公众号长文 4000-8000 字 + 经过 Claude Code harness 调 DeepSeek，和节点 5 原设计的场景（小红书短图文 + stdin/stdout 直调 DeepSeek）不重合。单凭这次不足以一次性给节点 5 拍板，短图文场景还没实测。

观察（sample = 1，小心引用）：
- Opus 4.7 风格还原最完整
- DeepSeek v4 Pro 中文比 Opus 松弛，SKILL 复杂规则服从弱一档
- DeepSeek v4 Flash 这次把任务做成了段落式压缩，SKILL 武器几乎没用上；还出现一次 Write 工具调用幻觉
- DeepSeek 后端跑 Claude Code 时，Anthropic 的 sensitive-path 保护不传递到子进程

接入路径记录：DeepSeek 当前可走两条路：
- **方式 A（节点 5 原计划）**：`~/.claude/scripts/deepseek` shell 包装，纯 LLM 生成，无 harness 开销
- **方式 B（本次实验跑通的）**：`claude --print --settings ~/.claude/settings.deepseek.json --model {opus|haiku} "..."`，带 Claude Code harness 和工具

哪条路在哪种场景更合适，等多跑几次再看。
