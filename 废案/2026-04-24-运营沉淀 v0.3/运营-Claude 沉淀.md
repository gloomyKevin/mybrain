# 运营-Claude 沉淀

> 基于 2026-04-22 会话与用户校准的内容方法论。**每次做内容前先读这份**。
>
> 这是 Claude 的执行层操作手册，和用户本人维护的 `运营.md`（外部链接收藏）区分。用户随时可改可删。

## §0 · 最根本的一条：立场即一切，而立场来自"底味"

去 AI 味不是文字润色问题，是**立场来源**问题。这个"立场"具体是什么？**底味**——用户自己的写作风格 DNA。

来自 dotey 在 X 的核心洞察（收录于 `Clippings/别再用提示词去 AI 味了，方向就是错的.md`）：

> **"你去不掉 AI 味。你只能用你自己的味道盖过去。"**
>
> AI 在用所有训练数据的**平均风格**写作——"最大公约数"。删掉某些词只能让菜不咸不淡，做不出你家厨房的红烧肉。真正的解法是：让 AI **学会你的味道**。

**操作含义（递进）**：

1. **轴心 = Claude 综合判断 → 永远是 generic AI base → 再怎么润色都是 AI 味**
2. **轴心 = 用户真实经验背书 → 立场偏离 generic → 降低 AI 味一个档**
3. **轴心 = 用户的写作风格 Skill（菜谱）→ 从根子上带上用户的底味 → 真正接近"像用户在说话"**

我们目前处在**第 2 档**：有用户的真实经验背书，但没有用户的个人写作菜谱。
- 这意味着我当下产出的任何内容即使过完所有 checklist，**仍会带"通用 Claude 味"**——因为我没学过用户的味道
- 第 3 档的路径是 dotey 的四步法（详见 §13），需要用户 3-5 篇真实原创作为训练起点
- 4/24 硬约束之前：不够时间建 Skill，只能用第 2 档硬凑
- 4/24 之后：启动 Skill 建设，用"用户改 Claude 的每一处"作为训练数据

## §0.5 · 这份文件自身的认知边界（诚实声明）

Claude 必须向自己承认三件事，避免把这份文件读成"圣经"：

1. **这份文件本身是 Claude 写的**——在没有用户个人 Skill 的情况下——所以它本身就带有 generic-AI-leaning 的痕迹（比如爱用结构化表格、爱排比、爱 N 条列举）。用户随时可以删改，不神圣。

2. **"方法论里用表格" ≠ "对外产出里可以用表格"**。方法论是给 Claude 看的操作手册，表格方便扫读；对外产出是要给人类看的内容，表格是 AI 最爱的"舒适结构"，用到要警觉。**不要让方法论文件的表格舒适感渗透到草稿里**。

3. **规则之上还有 taste**。规则是给没 taste 的兜底。用户的 taste > 规则 > 默认 generic AI。当用户直接告诉 Claude "这样写不对"时，用户的原话权重 > 本文件任何一条。本文件的作用是**把用户说过的东西系统化沉淀让 Claude 下次不再犯**，不是用来和用户辩论。

## §1 · 洗稿姿势：素材是输入语料，不是引用对象

**禁止痕迹词**：
- 「原帖说」「某大佬提到」「在论坛/小红书看到」
- 「XX 帖子 N 赞」「另一帖反对票」
- 任何把"这是洗别人的"暴露出来的结构

**正确姿势**：
- 默认第一人称视角（用户视角）
- 把素材当"综合信息源"内化进用户的判断/经验/踩坑叙事
- 具体例子归属改写成"我" / "我身边" / "我见过的"

**金句归属策略**：
- 非权威的（论坛用户、博主）→ 全部收归"用户自己的总结"
- 真权威（Karpathy、OpenAI 官方、学术论文）→ 明确挂名增权威感
- **临界：不能 100% 背书的权威不要蹭**

---

## §2 · 素材类型判别 → 差异化处理

动手前先分类，判不准**必须问用户**。

- 干货型 → 保留并深化成壁垒和深度，不扁平化成概述
- 营销型 → 学方法论/套路，按营销模式洗
- 观点争议型 → 提炼真正的分歧点，避免假辩论 / 情绪挑动无实质
- 故事案例型 → 提炼共性，第一人称重讲
- 情绪钩子型 → 研究其注意力捕获结构，学而不抄

典型翻车：把干货型扁平化成概述,细节丢光只剩总结。

## §3 · 去 AI 味

### §3.1 先警告：禁止清单 ≠ 底味

dotey 的判词："所有人用同一套去 AI 味提示词，产出的内容又变成了新的同质化。你从 AI 味 1.0 切换到了 AI 味 2.0。"

本章 §3.2-§3.4 是**禁止清单层**——只能帮 Claude 避免最典型的 AI 签名，**不能**给 Claude 任何"味道"。真正的味道建设在 §13。

### §3.2 AI 签名扫描 → 交给 humanizer-zh skill

战术层的 AI 签名检测和替换,使用 `运营/去AI味SKILL/SKILL.md`(humanizer-zh,基于维基 Signs of AI writing)。那份比本文原来自造的 26 条黑名单 + 人味动作清单更系统、更克制。

humanizer-zh 的 5 条核心:

1. **删填充短语** — 开场白、强调拐杖词(说实话 / 不得不说 / 值得注意的是)
2. **打破公式结构** — 避免二元对比、三段式强凑、戏剧分段
3. **变化节奏** — 句子长短混合,两项优于三项
4. **信任读者** — 直接陈述,跳过软化 / 辩解 / 手把手引导
5. **删金句** — 听起来像可引用的,重写

### §3.3 为什么不再自造"人味动作清单"

2026-04-24 与用户沟通确认:自造的"刻意人味动作"清单(段落不均匀 / 破折号 / 冗余插入语 / 刻意自嘲)结果是**反效果** — Claude 机械堆叠,从 AI 味 1.0(公式化升华)切到 AI 味 2.0(刻意破相 / 刻意灵光)。形式换,底没换。

真正出路:

- 不靠"表演真人"清单,靠用户**自己的写作样本建菜谱**(§13)
- 战术层用 humanizer-zh 删掉典型 AI 签名即可,不要在正向指导上叠加"怎么做得像人"的规则 — 那是 AI 2.0 陷阱

历史自造清单(§3.2 26 条 / §3.3 人味动作 / §3.4 机械词替换)存档于 `废案/去AI味-自造强规则-v0.3.md`,需要回看可去那里,不要再加进主文档。

### §3.5 同质化自检(§3 的终极检查)

每段写完反问：**"如果有 10 个 AI 用同样的素材在写同一个话题，我的这段文字会和他们长得完全一样吗？"**

- 会 → 还在 AI 味 2.0 → 回到 §0 找立场来源
- 不会 → 通过

## §4 · 干货密度 + 人味平衡

干货型收藏动力来自**密度**，但密度必须穿插 narrative 润滑。

**配方**：
- 钩子（100-150 字）：具体画面 + 真实情绪，不抽象
- 主体：N 条规则，每条包括一句话定义 / 具体举例 / 实操落地 / 偶尔一句吐槽或判断
- 结尾：**不收束式**(是否带私信钩见 §6,不强制)

**原则**：
- 具体画面 > 抽象概念
- 判断题 / 清单 > 对比表
- 可直接抄的配置片段 > 高屋建瓴

---

## §5 · 标题 / 封面情绪谱

**克制版**（时间投入感 + 克制自陈）：
- 「折腾快一年，最后就留这 N 条」
- 「用到现在，我项目里的 X 长这样」

**营销版**（冲突感 + 戏剧性）：
- 「被 X 搞崩溃 N 次后，我终于定下了这套规矩」
- 「没人告诉过你 X，所以你一直在 Y」

**原则**：
- 营销不能千篇一律——老套路（扣1、惊悚体、"颠覆认知"）正在快速掉价
- 第一条优先克制版（账号冷启，稳一点别像营销号）

## §6 · 钩子技巧

### §6.1 开头（前 100 字决定能不能留下读者）
- **具体画面** > 抽象描述
- 正确：「你让 Claude Code 写个登录功能。它写完了，你回头一看——根目录多了 what-i-did.md、方案对比-v3.md、临时思路-真的吗.md……」
- 错误：「AI 协作时代，文档管理是一个日益重要的话题」

### §6.2 结尾(选项,不强制)

**黑名单**(不用):

- 「你呢?评论区聊聊👇」—— 经典 AI 签名
- 「评论区扣 1」—— 2023 年小红书营销号模板,已掉价
- 「有没有同款?」「谁懂啊」—— 套路化

**可用选项**(自然选一种,不是每帖都套):

- 私信钩:「完整的 X 我打包成一份了,小红书贴不下 —— 想要的评论区冒个泡,我私发」
  - "冒个泡" 比 "扣1" 口语
  - 实际不必真发到评论区,让读者主动私信,拉高私信互动权重
- 自然收尾:陈述 / 动作 / 半句收束完事 —— 像人说完话就停了
- 留白:给一个具体动作作结("今晚打算试一下""明天上班先抄一条去"),不做升华

**关键判断**:这条帖子的内容值不值得有附加资料(比如完整 prompt 合集 / 配置片段) —— 值得就用私信钩,不值得就自然收。不要因为"首推私信钩"就每帖都套。

### §6.3 钩子一致性(仅当用钩时适用)
开头的具体画面和结尾的私信资料要**在同一个叙事场景里**。自然收尾 / 留白结尾不受此规则约束。

## §7 · 自评 + 不确定块 ritual

每次产出（骨架 / 试笔 / 草稿）结尾固定格式：

```
## 我的自评
- 我拿得准的：X Y Z
- 我拿不准、需要你拍板的：
  1. ...
  2. ...
```

**目的**：不装不猜。明确把瓶颈暴露给用户比硬装"我都搞定了"信任度高得多。

**拿不准最常见的类别**：
- 数字 / 具体时长（容易编得像信口开河）
- 账号定位向量
- 情绪强度（克制 or 营销）
- 具体文件名要不要落到真实项目
- 某个金句是否踩到 AI 签名

## §8 · 产出前 checklist（强制）

Claude 自身 taste 不如真人，每次产出前**强制过一遍**：

1. **立场检查(§0)**:这段话的立场来源是用户真实经验/真实情境,不是 generic AI?
2. **是否有个人底味(§13)**:`写作风格-菜谱.md` 存在吗?存在则必须 load;不存在则标注"当前无个人 Skill,硬凑"
3. **账号人设档**:如果是指定账号的文案(比如豆老师拜托了),先 load 对应账号的人设档
4. **类型判定(§2)**:识别到什么类型?对应策略是什么?
5. **§1 洗稿扫描**:帖子里有没有"原帖""某佬友""@作者 ID""论坛名""XX 帖 N 赞"这类痕迹词?非权威素材是否全部收归第一人称?这条经常栽,每次写完都要重扫
6. **humanizer-zh 扫描**:跑一遍 `运营/去AI味SKILL/SKILL.md` 的 5 条核心 + 词汇 / 结构 / 语气检查。不要自造"应该怎么做得像人"的规则去叠加
7. **同质化自检(§3.5)**:"10 个 AI 用同素材会不会写成一样?"
8. **钩子强度(§6.1)**:开头具体画面?
9. **结尾选择(§6.2)**:自然收 / 留白 / 私信钩 三选一,按内容值不值得附加资料判断,不默认走私信钩
10. **密度兑现(§4)**:干货型每条规则有具体举例 + 实操落地?有可抄的片段?
11. **平台印记(§12)**:按目标平台的印记约束过了吗?
12. **自评块(§7)**:结尾附"我拿得准 / 我拿不准"?

**未过 checklist 不交稿**。

## §11 · 工作流三层架构

```
收件箱.md  →  Clippings/        →  素材库/             →  草稿/<平台>/        →  已发布/
(唯一入口)    (原始采集)           (融会贯通，跨源)       (平台分发，按印记)       (存档 + 数据)
```

对应橙皮书 §06 Karpathy 的 `raw → wiki → output`，改造成内容生产版本。

### §11.1 第一层 · Clippings/（原始采集）

- **合并层**：用户用 Obsidian Web Clipper 手动 clip + Claude 从收件箱 URL 批量抓取，都塞这里
- **来源标记**：frontmatter 里用 `clipped_by` 区分
  - `clipped_by: user` — 用户手动 clip
  - `clipped_by: claude` — Claude 爬取
- 原封不动，**不做编辑**（编辑动作全部发生在下一层）
- 用户基本不看这层，主要给 Claude 读。但保留全文让 Claude 之后还能回溯

**Claude 抓取时的 frontmatter 模板**：
```yaml
---
title: 帖子原标题
source: 完整 URL
clipped_by: claude
clipped_at: YYYY-MM-DD
source_platform: linux.do / 小红书 / 即刻 / ...
---
```

### §11.2 第二层 · 素材库/（融会贯通）

- 一 topic 一文件，可跨多个原始源融合
- frontmatter 关联回第一层：`source_clippings: [[Clippings/xxx]]`
- 这一层做：抽干货 / 分派别 / 找角度 / 标盲点
- 不直接发布（离平台还差一步）

### §11.3 第三层 · 草稿/<平台>/<账号>/（平台 + 账号分发）

- 每个平台一个子目录：`草稿/小红书/` / `草稿/抖音/` / `草稿/公众号/`
- **平台下再按账号分子目录**：`草稿/小红书/豆老师拜托了/` / `草稿/小红书/<大号名>/`
  - 不同账号人设不同、定位不同,草稿要隔开
  - 每个账号的人设档路径 & 红线在 `运营/<账号名>-人设档.md`,产出前必 load
- 同一 topic 可以在多个账号子目录里并存多个版本(人设不同文案就不同)
- 文件名规则：`<YYYY-MM-DD>-<标题关键词>.md`（平台+账号已在目录层,文件名不重复）
- frontmatter 关联回第二层：`source_material: [[素材库/xxx]]`
- 这一层做：按平台印记（§12）+ 账号人设档套风格 / 控字数 / 调钩子 / 配图思路

### §11.4 "已发布" 层（存档）

- 命名规则（沿用 CLAUDE.md）：`<YYYY-MM-DD>-<平台>-<标题关键词>.md`
- 作用：发了就是档案；只补数据（阅读 / 点赞 / 收藏 / 评论 / 私信数），不改正文

## §12 · 平台印记 · 小红书 v0.1

> 印记 = 平台层面的"外骨骼规范"。当前只做小红书。抖音口播、公众号等其他平台后续增补。
> 这份是**平台印记**，不是**用户个人风格 Skill**——后者见 §13。

### §12.1 账号定位

**具体定位见各账号人设档**,不在本文件锁死:

- 豆老师拜托了 → `运营/豆老师拜托了-人设档.md`(29 岁杭州互联网打工人,AI 内容分享向)
- 未来若新建大号 → 相应人设档

本文件 §12 只讲**平台通用印记**(字数、语气、词汇避让、时间窗口等),定位和标签走人设档。

### §12.2 读者画像(通用,小红书场景)
- 时间有限,讨厌废话
- 有收藏 / 点赞习惯
- 私信互动成本相对低
- 具体到某账号的读者画像(是打工人还是技术人、年龄段、痛点)—— 见该账号人设档

### §12.3 正文规范
- **字数**：400-1000 字。干货型可上到 1000-1200，故事/观点型 400-600
- **开头**：前 3 行必须是具体画面或反常识判断——**绝不铺陈**
- **结构**：钩子 → 主体 → 私信钩子。避免总分总
- **语气**：技术人说话，不糖果色化。允许吐槽、自嘲、破相

### §12.4 平台化词汇避让
以下词汇**不用**——理由：账号走理性 / 工程向，用这些掉价：
- 绝绝子 / YYDS / 家人们 / 姐妹们 / 宝子们
- 救命 / 泪目 / 我哭了（无具体场景的情绪词）
- "姐妹推荐"「无限回购」这类美妆食品常用语态

**可用的平台口语**：
- 「翻车」「踩坑」「劝退」「真香」——技术圈共识词汇
- 「冒个泡」「聊聊」「扒一扒」——轻度互动语气

### §12.5 标签（tags）

- **共性原则**:3-5 个,不堆砌 10+(被平台判营销号风险)
- **具体标签组合**:随账号定位而定,见各账号人设档
  - 技术向账号常用:#AI写代码 #Claude #独立开发 #Cursor #vibecoding
  - 打工人向(豆老师拜托了)常用:#AI打工人 #ChatGPT #Prompt #打工人 #AI画图

### §12.6 结尾套路选择

## §13 · 用户写作风格 Skill 建设路径（4/24 之后启动）

> 来自 dotey 的四步法（`Clippings/别再用提示词去 AI 味了，方向就是错的.md`）。
> **这是从"AI 味 2.0"出到第 3 档的唯一路径**（§0 认知）。

### §13.1 为什么必须做
- 当前所有 §3 禁止清单本质是"删掉 AI 的套路"——删到最后只是让 AI 做菜不咸不淡，不是让菜有用户家味道
- 真正让内容"像用户在说话"的只有一种办法：AI 学过用户自己的样本

### §13.2 启动条件
- 4/24 硬约束之后启动（之前不碰，违反 Month 1-2 硬约束）
- 用户至少已有 3-5 篇自己真正满意的原创文章（可能是已发布的小红书 + 早期草稿 + 即刻随笔）

### §13.3 四步法

**第一步 · 让 AI 尝味道**
- 用户把 3-5 篇自己满意的原创喂给 Claude
- Claude 分析：用词偏好 / 句式习惯 / 结构特点 / 语气风格
- 生成初版 `写作风格-菜谱.md`（放根目录，独立文件）

**第二步 · 让 AI 照菜谱做菜，用户手改**
- Claude 按菜谱写新稿
- **用户必须自己动手改**（不能在对话里说"这里改一下"——dotey 明确指出那没用）
- 每次改动保留"改前 / 改后"两版

**第三步 · 根据反馈更新菜谱**
- 把 AI 原文和用户改版都喂给 Claude，用 dotey 的对比 prompt：
  > "对比以下两段文字，第一段是 AI 生成的原文，第二段是我手动修改后的版本。请分析我做了哪些修改，总结修改规律，并据此更新我的写作风格 Skill。"
- Claude 提取规律 → 更新 `写作风格-菜谱.md`

**第四步 · 反复做菜反复调味**
- 每篇都是一次迭代机会
- 约 3 次核心风格对上，5 次稳定，10 次 "AI 写得比用户自己还像用户"

### §13.4 菜谱文件结构（dotey 模板）
1. **角色与读者**：用户是谁 / 写给谁看
2. **风格要点**：3-5 条核心原则，每条带正反例
3. **禁止清单**：用户的忌口表（和 §3.2 的通用清单合并但用户专属加料）
4. **参考资料**：术语对照 / 常见错误 / 范文链接

### §13.5 菜谱使用规范
- Claude 每次产出前必须 load 菜谱（加入 §8 checklist）
- 菜谱是**活的**——不是写完就锁，每次迭代后增量更新
- 菜谱规模：dotey 自己迭代到 150 行用了几个月；我们目标前 3 个月到 50-80 行即可
- **菜谱文件不受本文件（§0.5）约束**——它是用户的口味档案，不是 Claude 的方法论
