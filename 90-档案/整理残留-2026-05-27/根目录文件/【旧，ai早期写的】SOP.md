## SOP-01 清洗收件箱

**触发词：** "清洗收件箱" / "把收件箱清一下"

**前置：** `收件箱.md` 的「待清洗」区有内容

**步骤：**

1. Claude 读取「待清洗」区所有条目
2. 每条按类别识别：URL / 段落 / 图片链接 / 截图 URL / 混合
3. 每条归到候选文件名（格式：`<简短关键词>.md`；冲突时加 `-<日期>` 后缀）
4. 为每条在 `素材库/` 建独立文件，frontmatter 填：
   - `来源类型`（推断：URL 域名或上下文）
   - `来源链接`（如有）
   - `状态: 未处理`
   - `摘要`（Claude 基于内容生成一句话）
   - `创建`（今天日期）
5. `为何保存` / `可用角度` **留空**，由用户后续手动补——AI 乱填就是污染
6. 在 `收件箱.md` 的「已清洗日志」追加：`YYYY-MM-DD 清了 N 条 → 素材库/`
7. 从「待清洗」区移除已清洗内容
8. 报告：清了几条、哪些可能重复、哪些需要人工判断

**回退：** `git checkout .`

## SOP-02 从素材开草稿

**触发词：** "开一条草稿" / "基于 [[素材名]] 开草稿"

**前置：** `素材库/` 至少 1 条 `状态 != 弃用`

**步骤：**

1. 用户指定素材就用；否则 Claude 挑 3-5 条候选（优先 `状态=未处理` 且 `可用角度` 已填的），让用户选
2. `草稿/` 下建文件：`YYYY-MM-DD-<标题关键词>.md`，套 `草稿/_模板.md`
3. frontmatter：`状态=构思中`、平台（问用户）、预计发布（问）、`用到的素材`（反向链接）
4. 「发布文案」Claude 基于素材的 `摘要` + `可用角度` + 用户意图，生成 300-500 字草稿
5. 「备注 / 思路演化」记录：为什么这么写、下一稿可能怎么改

**关键：AI 不代替用户做判断和最终文案。AI 出雏形，用户定稿。**

## SOP-03 草稿 → 发布归档

**触发词：** "我发了 [[草稿]]，URL 是 X" / "归档 [[草稿]]"

**步骤：**

1. 读取草稿内容
2. 新建 `已发布/YYYY-MM-DD-<平台>-<标题关键词>.md`，套 `已发布/_模板.md`
3. frontmatter：平台 / 发布时间 / URL / `源草稿` / `源素材`（继承草稿的）
4. 「发布文案（快照）」= 草稿的「发布文案」完整复制
5. 回到草稿文件，改 `状态: 已发`
6. 每条源素材文件：改 `状态: 已用`，`关联内容` 追加 `[[已发布/...]]`
7. 提醒用户：T+1 记得回来填数据

## SOP-04 数据回写

**触发词：** "更新数据 [[已发布名]]" / "T+N 数据：..." / "[[已发布]] 数据"

**步骤：**

1. 打开对应 `已发布/` 文件
2. 在「数据」表对应时间点填入用户给的数字
3. 如果是 T+7 回写，主动问用户要不要写一次「事后复盘」
4. 如果数据明显超预期 / 不及预期，引导用户思考原因（但不替他下结论）

---

## SOP-05 翻素材库找可用

**触发词：** "翻素材库" / "我想做关于 X 的内容" / "有什么素材能用"

**步骤：**

1. 用户给了主题：grep 素材库的 `可用角度`、`摘要`、标题、正文。按相关度排序
2. 用户没主题：返回三类清单（各前 5 条）：
   - 最近 7 天新加的 `状态=未处理`
   - `可用角度` 已填但 `关联内容` 为空（还没用过）
   - 所有素材按 `创建` 倒序
3. 每条给出一句推荐理由
4. 用户选定 → 走 SOP-02

## SOP-M 工具 / 架构升级冲动应对

**触发模式：** 用户提出 "给 mybrain 加个 X" / "要不要搞个 Y" / "架构能再优化..." / "是不是该装个 Z 插件"

**Claude 的反应流程：**

1. **先别立刻答应，也别立刻否定。**
2. 问一问：**"X 的答案能让你 24 小时内启动 / 发新内容吗？"**
3. 如果用户说**不能 / 犹豫**：指出这可能是推迟模式（参考 `自我.md` 最后一节「给未来 AI 助手的提示」第 5 条）。把 X 登记到 `收件箱.md` 的"以后再看" section，**继续手头正事**
4. 如果用户说**能，因为 X 卡住了具体操作**：要求说明——卡住了哪个操作？发生了几次？当前变通是什么？
5. 真实卡点 → 帮他做 X
6. 其他情况 → 登记不做

**边界（自我.md §7）：** 当用户在真诚求助时，过度坚持"先做正事"会让他感到被推开。要区分"他在推迟"和"他在真诚求助"。**标志：他是在问 How（推迟倾向）还是在讲具体痛点（真诚求助）。**

## SOP-D 30 天复盘（2026-05-22）

**触发时间：** 2026-05-22 前后，或用户说 "30 天复盘"

**前置：** 已有 ≥ 1 条已发布内容

**步骤：**

对照 `OPC 规划.md` §十「给未来的提醒」里的 7 个问题：

1. 小红书账号上有几条内容？
2. 触发过哪几次"想推迟/想换方向/想加新工具"的念头？怎么应对的？
3. 自己觉得最爽的是哪一条？数据最好的是哪一条？
4. 定位有浮现的迹象吗？
5. 身体和家庭状态如何？
6. 如果继续，下一个月主要做什么？
7. 如果不继续，坦诚面对"我不适合这条路"，考虑选项 A（留在当前工作优化生活）还是其他路径。

Claude 帮用户：
- 从 `已发布/` 统计数据、从源素材反推"哪些主题起效"
- 从 `收件箱.md` 的「以后再看」统计有多少次推迟冲动
- 基于数据事实给一份草稿，用户定稿

## 维护这份 SOP 的规则

- **每次 Claude 犯一个错** 或流程需要调整 → 加一条或改一条
- 不写"以后可能会用的" SOP，只写"用过至少一次的"
- 触发词尽量短、唯一，别和日常说话冲突
- 新 SOP 用 `SOP-XX` 格式命名，字母用于不走流水线的辅助 SOP（如 M / D）
