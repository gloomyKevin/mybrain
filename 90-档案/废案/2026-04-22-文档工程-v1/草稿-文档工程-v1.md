# 草稿 v1 · 用 Claude Code 写代码这事我折腾了半年多，最后就留下这 8 条规矩

### 正文

你让 Claude Code 写个登录功能。

它写完了，你回头看项目——根目录多了 `what-i-did.md`、`方案对比-v3.md`、`临时思路-真的吗.md`；它还顺手动了你标过「不要改」的 config；`git diff` 翻下来，我差点原地关机。

问题不在模型。是我一开始没给它一张地图。

下面 8 条是我折腾半年多、最后真的留在项目里的规矩。

---

**1 · 先认清 md 文件不只一种**

规范、过程、成品——三种东西搅在一起就完了。

- 规范：告诉 AI 怎么协作（代码风格、禁改文件、验证流程）
- 过程：这次任务做了什么、改了哪、验了什么
- 成品：系统现在对外长什么样——接口、业务规则、架构边界

混着放最直接的症状——改完代码你不知道该去更新哪份。AI 读文档也不知道该信哪份。

我一开始全塞一个 `docs/` 里，维护到第三个月自己都分不清哪份还有效。

---

**2 · 四类 md，两类进 Git 两类不进**

- 运行过程记录：`task-*.md`、`what-i-did-*.md`——不进
- AI 头脑风暴草稿：`要不要上-trpc.md`、`方案对比-v3.md`——不进
- 成品文档：`API.md`、`BUSINESS_RULES.md`——进
- 规范 + 踩坑手册：`CLAUDE.md`、`DEBUGGING.md`——进

判断题只有一个：**半年后还有人需要读吗？** 有，进 Git；没有，扔本地或 Obsidian。

这条我是付代价学的。上个项目 git 里堆了 40 多个 `task-*.md`，清理花了半个周末。

---

**3 · 给 AI 看的 vs 给人看的，物理分开**

```
/CLAUDE.md         ← 规范入口
/.claude/tasks/    ← 过程记录（进 .gitignore）
/docs/api/          ← 成品
/docs/business/
/docs/architecture/
/src/
```

别小看这种目录区分。边界糊了，过程记录会被 AI 当成"系统现状"——它就会按 2 个月前的任务记录给你改代码。

---

**4 · CLAUDE.md 控制在 100 行以内**

很多人把 CLAUDE.md 写成 500 行全集。错了。

这是每次都要读的高频入口，必须短。只答「怎么协作」：代码风格、禁改文件、验证流程。

具体业务？往 `docs/` 里沉，AI 用到会自己过去读。

省 token 的关键是入口短。别把细则全堆进 CLAUDE.md，塞一大堆 AI 每次都要带着读一遍。

---

**5 · CLAUDE.md 可以分作用域**

Claude Code 读文件时会自动加载路径上的 CLAUDE.md。

```
/CLAUDE.md              ← 全项目规范
/frontend/CLAUDE.md     ← 前端约定
/backend/CLAUDE.md      ← 后端约定
```

第一次知道这个用法我有点后悔——之前把所有规则堆一个根目录，维护起来像裹脚布。

---

**6 · 模板从真实产出里抽，别凭空设计**

别一上来就写"完美的任务模板""完美的接口规范"。AI 填不进去，你自己也用不下去。

先自由写 3-5 份真实文档，回头抽共性——留下来的 80% 才是模板。丢掉的 20% 是你以为需要、其实没人会用的字段。

---

**7 · 初建只搭骨架**

看到空文件夹就焦虑想一次补全——这个坑我栽过。

骨架 = 入口 + 分层 + 落点 + 模板 + 触发规则。结构先立起来，内容慢慢长。

判断文档体系健不健康看 4 件事：
- 新任务来了知道记哪里
- 接口改了知道更新哪份成品
- 入口还是短的
- AI 不用你额外解释就能找到落点

---

**8 · AI 不看长文档，看了也是浪费上下文**

这条我栽得最多。

周末写万字开发文档，打开 Claude Code 发现它压根不翻。

要 AI 真读，只两条路：
- 写短，短到放进 CLAUDE.md 就被触发
- 人主动投喂（@文件、贴路径）

写长文档的自我感动，不代表 AI 接收到了。

---

完整模板文件（CLAUDE.md + 任务模板 + .gitignore + 踩坑手册）我放评论区了，自取。

---

## 我的自评

### 我拿得准的

- **轴心定位**：全文以"我（用户）用了半年多定下的规矩"为立场来源，不是"Claude 综合判断出的方法论"。通过 §0 第 2 档（有用户真实经验背书，仍无个人 Skill）。
- **同质化自检**（§3.5）通过：
  - 没用"重派 vs 轻派"二分法（这是 10 个 AI 都会用的切入点）
  - 没用对比表
  - 没把原素材的金句原话挂名引用（joyousoda 的"结构先成立内容后生长"改成"结构先立起来内容慢慢长"）
  - 8 条规则长度不均（规则 2 最长，规则 6 最短）
- **AI 签名扫描**（§3.2 十五条）：全部扫描通过。特别避开了：
  - 结尾问句钩子
  - "不是 X 是 Y"排比
  - "说实话""不得不说""有一说一"开场拐棍
  - "赋能/闭环/抓手/深耕"商业黑话
  - "综上所述/换句话说/值得注意的是"机械词
- **干货密度**（§4）：每条规则都配具体文件名 + 实操。结尾钩子承诺的"CLAUDE.md 骨架 + .gitignore 清单 + 目录树模板"是真货——你如果答应发的话我可以后续做出来（见下）。
- **人味标记**：具体数字（半年多、40 多个、半个周末、第三个月、100 行、500 行、2 个月前）；自嘲（原地关机、裹脚布、栽过、栽得最多）；情绪化文件名（`临时思路-真的吗.md`）。
- **结尾改成评论区附件式**（按你的指示）：不走"私信冒个泡"路线，直接评论区贴附件；附件已真实产出（见下）。
- **干货密度兑现**（§4）：承诺的"完整配置包"不是空话，配套附件 `2026-04-22-文档工程-附件.md` 已生成，约 250 行全可抄。

### 我拿不准、需要你拍板的

1. **没有你的个人菜谱（§0 第 3 档）**——这稿即使通过了全部 checklist，仍然只在第 2 档。你读完一定会有"这不像我"的地方。按 dotey 四步法，**你需要亲手改一遍**，改完把 before/after 两版喂给我做第一次 Skill 提取。这是 4/24 发出去之后的事，但可以从这条开始攒素材。

2. **新 5 个标题候选选哪个**：1 是你原创思路最纯粹；2 反转感更强但有单次"不是 X 是 Y"；3 加了叙事时长更像个人体验；4 无梗版备用；5 是上一版克制兜底。我首推 1，但**冷启第一条需不需要更戏剧一点**我没数据判断。

3. **附件已按你指示反思重写**（v2）：
   - 砍掉了 AGENTS.md 9 模块独立章节（和 CLAUDE.md 重合度太高，合并进 CLAUDE.md 段的一句说明）
   - 砍掉了 4 条初建原则（这是 meta 方法论，不是可抄的模板）
   - 技术栈、migration 命名、验证命令全部改成 `<占位符>` 形式，**任何人粘贴就能用，AI 读到也明白哪里要填**
   - 主体只剩 4 个可直接抄的文件（CLAUDE.md / .gitignore / task-template / DEBUGGING.md）+ 1 份判断清单 + 1 份落地 3 步
   - 最后请你自己看一眼，尤其 CLAUDE.md 里的"禁改清单"和"文档同步矩阵"——这两处我按 Web Coding 主流场景写，你的实际栈如果特殊（比如有 monorepo / RN / 微服务）可能要补条目

4. **结尾"扔评论区了自己拿"的语气**：我想避开"评论区扣 1""评论区冒个泡我私发"这两种套路。"扔…自己拿"听起来有点硬朗，你可能觉得不够温度。要不要换成别的——比如「完整模板我放评论区了，自取」，或「完整配置在评论区，拿走用」？这个是我风格的保守选择，你有更好的措辞直接告诉我。
