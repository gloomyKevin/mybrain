## 仍然不通过的项 ❌

### L1 硬性规则 ❌（多处违反）

**冒号「：」违反 5+ 处**：
- 「让我看清一件事：吭哧吭哧做单条内容指望大爆」
- 「我观察到一件事：对创业者来说」
- 「我做了个工具：输入你的产品URL」
- 「但做着做着发现两个卡点：一是已经一堆人在做」
- 「我发现一个共同模式：一开始都是个挺小的事情」
- 「给自己定一条规矩：所有事情先做一个 24 小时之内」

**破折号「——」违反 2 处**：
- 「这东西怎么说呢，太离谱了——你不用关心底层怎么写的」
- 「事后我才明白——我做了自己不了解的行业里的事」

**双引号违反 1 处**：
- 「想起以前看过一个概念叫"布里丹之驴"」（应当用「」或不加引号）

**结构禁令违反**：
- 4 处 `---` 分隔线
- 标题前用 `# `（markdown 一级标题，小红书纯文本不用）

### L4 致命错误 · 复述了卡兹克本人的"固定尾部" ❌❌

文末出现：

```
以上，既然看到这里了，如果觉得不错，随手点个赞、在看、转发三连吧～
谢谢你看我的文章，我们，下次再见。
> / 作者：卡兹克
```

这是 SKILL 里给「卡兹克本人公众号文章」用的固定尾部。DeepSeek 死板复述了 SKILL 模板里的尾部样板，**没理解这是卡兹克本人的文末身份签名**，不是给所有按这风格写文的人套用的。

更严重：把**作者署成了卡兹克**——这是 OPC 用户的文章，不是卡兹克的。如果照原样发布，等于冒认作者身份。

### 内容禁令违反 1 处 · 虚构细节

- 「我就是那个一边焦虑得半夜两点还在刷论文，一边动手试了又试」

「半夜两点还在刷论文」是 DeepSeek 自己虚构的细节，用户原话里没有这个具体场景。违反 SKILL「假设性例子大忌」「不编造场景」原则。

## 自检小结

| 层 | v1 | v2 |
|---|---|---|
| L1 硬性规则 | ❌ 严重违反 | ❌ 仍然违反（冒号 5+ / 破折号 2 / 双引号 1 / 分隔线 4）|
| L2 风格一致性 | ❌ 全是 label | ⚠️ 大体可以，但分隔线打断节奏 |
| L3 内容质量 | ⚠️ 部分 | ⚠️ 部分（虚构细节 1 处）|
| L4 活人感 | ❌ PPT 脚本感 | ❌ **被错误的固定尾部 + 卡兹克署名重创** |

**总评 v2**：比 v1 进步明显，但 L1 标点禁令和 L4 文末签名两处仍然不达标。

## 关键观察 · DeepSeek 在 SKILL 系统级喂养下的真实能力

把 SKILL 放 system role + 自然语言骨架，**消除了 v1 的 label 复述问题**，文章本身的叙事和结构有质变。但暴露出两个 DeepSeek 的真实弱项：

1. **标点禁令在长 system prompt 下记不住**：SKILL 里反复强调「不用冒号、不用破折号、不用双引号」，但 v2 仍然全部命中。这说明 DeepSeek V4 Flash 在长 system prompt（约 30K tokens）下，对**反复强调的硬规则**记忆和执行力度不够
2. **死板复述 SKILL 模板**：固定尾部、卡兹克署名这种"明显不应该套用到他人文章"的内容，DeepSeek 没做语义判断，机械搬运

Claude Opus 4.7 在同等约束下既不犯标点错也不复述卡兹克尾部。**这两条是 Claude 的指令理解优势在长 prompt 下的体现**。

## 公平评分（如果你用了人工修复）

如果用户花 3-5 分钟人工修复 v2：
- 删 ` ---` 分隔线 → 节奏立刻干净
- 把所有 `：` 换成句号或逗号 → L1 通过
- 把 `——` 换成逗号 → L1 通过
- 把 `"布里丹之驴"` 改成 `「布里丹之驴」`
- **删掉文末「以上，既然看到这里了...」一整段** → L4 通过
- 删掉 `# `

修复后 v2 的内容质量足够发布，且有一些 v1 和 Claude 版没有的亮点（"半夜两点刷论文"虚构需要替换 / "站在中间发呆，不知道从哪里下嘴"可以保留）。

但**这个工作流不能称作"用 DeepSeek 自动出稿"**——它需要每次人工修标点和删尾部，不是流水线。
